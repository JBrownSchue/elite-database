# ELITE Document Database

ELITE Document Database is a small file-based document database for flexible product data.

It was created as a demonstration for eCommerce product data where different product types require different attributes. A T-shirt can have a size and material, a board game can have a publisher and player count, and a book can have an ISBN and author.

The project provides:

- A reusable Python database library
- A PySide6 desktop GUI
- One JSON document per record
- Collections for grouping documents
- Automatically generated indexes
- Revision history for changed and deleted documents
- Search and nested-field filtering
- A simple attribute editor that does not require users to write JSON

## Why this database format?

A traditional product table requires many columns that are empty for most products. This database stores each product as an independent JSON document. Each document can contain its own attributes while still following a consistent basic structure.

The database is designed to be easy to inspect, copy, migrate and demonstrate. It is not intended to replace a production database server for large-scale or concurrent workloads.

- Python 3.14 or newer
- `uv` or `pip`

## Database layout

After creating or migrating a database, the directory has this structure:

```text
database/
├── manifest.json
├── documents/
│   └── products/
│       ├── prod-001.json
│       └── prod-002.json
├── indexes/
│   └── products.json
└── history/
    └── products/
        └── prod-001/
            └── revision-0001.json
```

### `manifest.json`

The manifest identifies the database format and registered collections.

### `documents/`

Each record is stored in its own JSON file. This keeps individual documents easy to read and change.

### `indexes/`

Indexes are generated by the library. They contain document paths and type information. Users should not edit index files manually.

### `history/`

Previous versions are stored when a document is updated or deleted.

## Python API

The library is located in:

```text
src/data/elitedb.py
```

Import it with:

```python
from data.elitedb import Database
```

### Create a database

```python
from data.elitedb import Database

database = Database.create("database")
```

Create a products collection if it does not exist:

```python
if "products" not in database.collections_list():
    database.create_collection("products")
```

### Load an existing database

```python
from data.elitedb import Database

database = Database.load("database")
```

`Database.load` expects a directory containing a valid `manifest.json`.

### Create a collection

```python
database.create_collection("products")
database.create_collection("customers")
database.create_collection("orders")
```

Collection names may contain letters, numbers, underscores and hyphens.

### List collections

```python
collections = database.collections_list()
print(collections)
```

Example result:

```text
['customers', 'orders', 'products']
```

### Insert a document

```python
product = {
    "id": "game-001",
    "type": "board-game",
    "sku": "GAME-001",
    "name": "Fantasy Quest",
    "category": "Brettspiele",
    "brand": "Beispielverlag",
    "stockQuantity": 35,
    "isActive": True,
    "attributes": {
        "publisher": "Beispielverlag",
        "minimumPlayers": 2,
        "maximumPlayers": 5,
        "playingTimeMinutes": 90
    }
}

database.insert("products", product)
```

Every document requires a unique `id`. The library automatically adds or updates metadata such as the document type, creation time, update time and revision number.

### Read one document

```python
product = database.get("products", "game-001")

if product is not None:
    print(product["name"])
```

`get` returns `None` when the document does not exist.

### Read all documents

```python
products = database.all("products")

for product in products:
    print(product["id"], product["name"])
```

### Update a document

```python
product = database.get("products", "game-001")
product["stockQuantity"] = 42
product["attributes"]["maximumPlayers"] = 6

database.update("products", "game-001", product)
```

Before updating, the previous document is automatically copied to the history directory.

### Delete a document

```python
database.delete("products", "game-001")
```

Deleted documents are also stored in the history directory before removal.

### Search documents

Search all fields of every document in a collection:

```python
results = database.search("products", "fantasy")

for product in results:
    print(product["name"])
```

Search with a nested-field filter:

```python
results = database.search(
    "products",
    category="Brettspiele"
)
```

Nested paths can be used for filters:

```python
results = database.search(
    "products",
    **{"attributes.publisher": "Beispielverlag"}
)
```

### Rebuild an index

Indexes are rebuilt automatically after inserts, updates and deletes. They can also be rebuilt manually:

```python
database.rebuild_index("products")
```

### Read revision history

```python
revisions = database.revisions("products", "game-001")

for revision in revisions:
    print(revision)
```

History is useful for demonstrating how document databases can preserve previous states.

## Migrating the existing JSON file

The original project uses a single `database.json` file. It can be migrated into the document database format without modifying the original file.

Create a migration script or run this code from the project root:

```python
from data.elitedb import migrate_json

migrate_json(
    source="database.json",
    destination="database",
    collection="products"
)
```

The result is one JSON file per product under:

```text
database/documents/products/
```

## GUI workflow

The GUI is designed for users who do not know JSON.

1. Start the application.
2. Search or filter products using the controls above the table.
3. Select a product to view its details.
4. Double-click a product or select `Bearbeiten` to edit it.
5. Use `＋ Eigenschaft hinzufügen` to add custom attributes.
6. Select the attribute type and enter its value.
7. Save the product.
8. Use `Löschen` to remove a selected product.

Supported custom attribute types include:

- Text
- Number
- Yes or No
- Multiline text

## Example: different product types

A clothing product can contain:

```json
"attributes": {
  "size": "L",
  "color": "Black",
```

A board game can contain:

```json
"attributes": {
  "publisher": "Example Publisher",

  "maximumPlayers": 5,

}
```

```json

  "publisher": "Example Publisher"
}
```

All three products can exist in the same collection without requiring a table migration.

## Error handling

The library raises normal Python exceptions for invalid operations:

- `ValueError` for invalid documents, collections or duplicate IDs
- `KeyError` when updating or deleting a missing document
- `FileNotFoundError` when loading a missing database
- `json.JSONDecodeError` when a JSON file is invalid
- `OSError` for file-system errors

Applications using the library should catch these exceptions and show an appropriate message to the user.

## Scope and limitations

This project is intended as an educational demonstration and a lightweight local data store.

It does not currently provide:

- Multi-user concurrency control
- Transactions across multiple documents
- Network access
- Authentication or permissions
- Database-server scalability
- Automatic conflict resolution

For a large production e-commerce system, a server-based document database such as MongoDB or a relational database with a carefully designed flexible attribute model would be more appropriate.
